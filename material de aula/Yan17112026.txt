Questionário de Revisão — UC10: Gerenciamento de Configuração e Versionamento de Softwares

1. Diferença entre reset e revert: Explique a diferença fundamental entre o funcionamento dos comandos git reset e git revert ao desfazer alterações em um projeto, detalhando o que ocorre com o histórico de commits em cada caso.

R: git reset possui a utilidade de desfazer alterações em um repositório, já o revert desfaz alterações no projeto sem exclui-las. 

2. Significado de HEAD~1: No contexto do comando git reset HEAD~1, o que a expressão HEAD~1 representa e qual é o resultado prático dessa operação na branch atual?

R: tem a função de demonstrar quantas ações precisam ser feitas

3. Uso do --amend: Em quais situações um desenvolvedor deve utilizar a opção --amend no comando git commit? Cite pelo menos dois exemplos de modificações que podem ser feitas com esse recurso.

R: Utiliza-se para modificar o último commit de forma que não perca seu progresso já feito, permitindo, por exemplo, consertar um erro de digitação na mensagem do commit ou adicionar um arquivo esquecido que deveria ter entrado no envio anterior.

4. Estrutura do Gitflow: Descreva o objetivo do modelo de colaboração Gitflow e explique a função de cada uma de suas cinco branches principais (Main, Develop, Feature, Release e Hotfix).

R: O Gitflow serve para organizar o desenvolvimento em equipe e funciona com cinco branches: a Main guarda o código oficial em produção, a Develop junta as novidades que estão sendo feitas, a Feature serve para criar uma função nova sem atrapalhar os outros, a Release é usada para testar tudo antes de lançar, e a Hotfix serve para corrigir erros urgentes direto no sistema oficial.

5. Vantagens do Gitflow no ciclo de vida: De que maneira a criação e a fusão de ramificações no modelo Gitflow ajudam a evitar conflitos durante o desenvolvimento de um software?

R: Ajuda porque cada pessoa desenvolve a sua parte separada nas suas próprias branches sem mexer no código dos colegas, deixando para juntar tudo de forma organizada na Develop só quando estiver pronto, o que evita que o projeto quebre toda hora.

6. Funcionamento do Trunk-Based Development: Como funciona o modelo Trunk-Based Development e qual é a principal justificativa para adotá-lo em um projeto?

R: Nesse modelo todo mundo manda pequenas alterações direto para uma única branch principal várias vezes ao dia, e a principal justificativa para usar ele é entregar atualizações mais rápido e evitar aqueles conflitos enormes que acontecem quando se demora muito para juntar os códigos.

7. Boas práticas no Trunk-Based Development: Como todas as alterações no Trunk-Based Development são feitas diretamente na branch principal, quais práticas são consideradas fundamentais para evitar conflitos no projeto?

R: Para não dar problema mexendo direto na branch principal, é fundamental fazer commits bem pequenos e frequentes, atualizar o código do seu computador várias vezes ao dia e ter testes automatizados rápidos para avisar na hora se alguma alteração quebrar o sistema.

8. Problemas do armazenamento centralizado sem versionamento: Antes do surgimento das ferramentas de controle de versão, múltiplos usuários acessavam um mesmo arquivo em um servidor central. Quais eram os dois principais problemas que ocorriam quando duas ou mais pessoas tentavam editar esse arquivo simultaneamente?

R: Os dois principais problemas eram a sobrescrita de dados, quando uma pessoa salvava o arquivo por cima do outro e apagava o trabalho do colega sem querer, e a perda de histórico, pois não dava para saber quem mudou o quê nem voltar para uma versão anterior que funcionava.

9. Sistemas centralizados vs. distribuídos: Qual era a principal vulnerabilidade das ferramentas antigas de controle de versão centralizado (como CVS e Subversion) em caso de falha no servidor, e como os Sistemas de Gerenciamento de Versões Distribuídos (SGVD), como o Git, resolvem esse problema?

R: A vulnerabilidade dos sistemas antigos é que se o servidor central desse problema ou parasse de funcionar, ninguém conseguia trabalhar e todo o histórico podia ser perdido, já o Git resolve isso porque cada pessoa tem uma cópia completa do projeto e de todo o histórico no seu próprio computador, permitindo restaurar tudo facilmente.

10. Popularidade do Git e papel do GitHub: Além de ser um sistema distribuído e performático, qual é o papel da plataforma GitHub na ampla adoção do Git pela comunidade de desenvolvimento e pelo ecossistema open-source?

R: O GitHub ajudou o Git a ficar tão popular porque criou um site fácil e visual onde os programadores podem guardar seus códigos de graça na internet, mostrar seus projetos para outras pessoas e colaborar em programas de código aberto de um jeito simples.
