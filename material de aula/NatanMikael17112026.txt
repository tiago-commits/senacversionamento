Questionário de Revisão — UC10: Gerenciamento de Configuração e Versionamento de Softwares

1. Diferença entre reset e revert: Explique a diferença fundamental entre o funcionamento dos comandos git reset e git revert ao desfazer alterações em um projeto, detalhando o que ocorre com o histórico de commits em cada caso.

--
1R. A diferença fundamental entre o git reset e o git revert está em como eles lidam com a linha do tempo do projeto, o reset apaga o histórico, enquanto o revert preserva o histórico criando um novo registro
--

2. Significado de HEAD~1: No contexto do comando git reset HEAD~1, o que a expressão HEAD~1 representa e qual é o resultado prático dessa operação na branch atual?

--
2R. A HEAD~1 significa "commit antes do commit atual", o resultado prático é desfazer o último commit da branch atual, voltando o ponteiro do projeto para o estado anterior, mas mantendo as alterações nos arquivos locais
--

3. Uso do --amend: Em quais situações um desenvolvedor deve utilizar a opção --amend no comando git commit? Cite pelo menos dois exemplos de modificações que podem ser feitas com esse recurso.

--
3R. O comando --amend é usado para omodificar último commit realizado, substitui o anterior por um novo alterando o seu hash/id) em vez de criar um novo
--

4. Estrutura do Gitflow: Descreva o objetivo do modelo de colaboração Gitflow e explique a função de cada uma de suas cinco branches principais (Main, Develop, Feature, Release e Hotfix).

--
4R. Gitflow é um modelo de ramificação (branching) criado para organizar o desenvolvimento de software em equipe e gerenciar ciclos de lançamento estruturados

Main guarda o histórico de lançamentos
Develop funciona como a branch de integração para o desenvolvimento contínuo
Feature é usada para desenvolver novas funcionalidades
Release prepara uma nova versão para produção
Hotfix destinada a corrigir erros críticos encontrados em produção de forma imediata
--

5. Vantagens do Gitflow no ciclo de vida: De que maneira a criação e a fusão de ramificações no modelo Gitflow ajudam a evitar conflitos durante o desenvolvimento de um software?

--
5R. Evita conflitos ao isolar cada tipo de trabalho em ramificações separadas e estabelecer pontos de integração bem definido
--

6. Funcionamento do Trunk-Based Development: Como funciona o modelo Trunk-Based Development e qual é a principal justificativa para adotá-lo em um projeto?

--
6R. É um modelo de controle de versão onde todos os desenvolvedores integram suas alterações frequentemente diretamente em uma única branch principal, é a principal justificativa para eliminar os grandes conflitos de merge e acelerar a entre contínua
--

7. Boas práticas no Trunk-Based Development: Como todas as alterações no Trunk-Based Development são feitas diretamente na branch principal, quais práticas são consideradas fundamentais para evitar conflitos no projeto?

--
7R. Integração diária em pequenos lotes e automação rigorosa de testes 
--

8. Problemas do armazenamento centralizado sem versionamento: Antes do surgimento das ferramentas de controle de versão, múltiplos usuários acessavam um mesmo arquivo em um servidor central. Quais eram os dois principais problemas que ocorriam quando duas ou mais pessoas tentavam editar esse arquivo simultaneamente?

--
8R. Sobrescrita acidental de alterações (perda de dados) e o bloqueio de produtividade
--

9. Sistemas centralizados vs. distribuídos: Qual era a principal vulnerabilidade das ferramentas antigas de controle de versão centralizado (como CVS e Subversion) em caso de falha no servidor, e como os Sistemas de Gerenciamento de Versões Distribuídos (SGVD), como o Git, resolvem esse problema?

--
9R. A principal vulnerabilidade dos sistemas centralizados era o ponto único de falha, todo o histórico completo do projeto ficava armazenado em um único servidor central, o que causava a paralisação imediata da equipe e o risco de perda total dos dados caso esse servidor saísse do ar ou tivesse seu disco corrompido. Os Sistemas de Gerenciamento de Versões Distribuídos, como o Git, resolvem esse problema fazendo com que cada desenvolvedor tenha uma cópia completa de todo o repositório
--

10. Popularidade do Git e papel do GitHub: Além de ser um sistema distribuído e performático, qual é o papel da plataforma GitHub na ampla adoção do Git pela comunidade de desenvolvimento e pelo ecossistema open-source?

--
10R. O GitHub desempenhou um papel na popularização do Git ao transformá-lo de uma ferramenta complexa de linha de comando em uma rede social e visual para desenvolvedores
